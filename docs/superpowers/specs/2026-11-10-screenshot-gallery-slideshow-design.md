# Screenshot Gallery Slideshow Design

## Intent

Keep the screenshot gallery's page-grouped overview, but let users inspect all
screenshots as one continuous slideshow instead of navigating away to a single
image. The slideshow must begin at the card that was clicked, use the same
order as the gallery, and support touch swiping for quick visual review.

## Requirements

- Clicking a screenshot card opens an in-page slideshow rather than a new image
  page or tab.
- The first slide is the clicked image.
- Navigation traverses every screenshot in gallery display order, across page
  group boundaries.
- Previous/next controls, left/right keyboard arrows, and touch swipes move
  between slides; navigation wraps at both ends.
- Escape and the close control return to the gallery overview.
- The slideshow presents the image, filename, current position, and an
  accessible label; the existing gallery grouping and image URLs remain
  unchanged.
- The slideshow uses the available viewport as fully as practical, minimizing
  outer margins while preserving compact controls and the image caption.
- No third-party JavaScript dependency is added.

## Approach

Use a native HTML `<dialog>` generated by the existing Python gallery builder.
The builder flattens the page-group output order into one serialized image list
and each card carries its global starting index. A small inline script owns the
current index, updates the dialog, handles keyboard and pointer/touch gestures,
and closes the dialog. This keeps the server's static-file behavior intact and
avoids a second slideshow route.

## Verification

Extend the existing Python gallery tests to verify that cards are slideshow
triggers, group image lists and start indices are emitted, and the dialog
contains the navigation/close affordances and gesture handlers. Run the full
gallery unit test file and the repository's relevant formatting checks.
