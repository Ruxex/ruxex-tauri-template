# プロジェクト詳細画面の表示・操作改善

## 意図

プロジェクト詳細画面を、プロジェクト名が分かるナビゲーションと、チャットを中心にした用語・操作で利用できるようにする。

## ゴール

- パンくずを `Projects > プロジェクト名` とし、`Projects` から `/projects` に戻れるようにする。
- プロジェクト詳細画面内の `task` 表記を `chat` に統一する（`New chat`、`Chats`、空状態メッセージを含む）。
- 詳細画面からプロジェクト名・ワークスペースルートを編集できる。
- 詳細画面から削除確認を経てプロジェクトを削除でき、削除後は `/projects` に戻る。

## 非ゴール

- サイドバー、検索画面、チャット画面などプロジェクト詳細画面以外の `task` 表記変更。
- プロジェクト用の新しい専用ルートの追加。
- プロジェクトのメタデータ・並び順の編集UI。

## 制約

- 既存の `project/read`、`project/update`、`project/delete` App Server APIを利用する。
- UIは既存の `ProjectHomePage` 内のダイアログ方式とし、画面遷移を増やさない。
- 編集成功時は詳細表示を更新し、削除成功時はプロジェクト一覧キャッシュを更新する。
- 更新・削除失敗時は詳細画面にエラーを表示し、入力内容と画面を維持する。

## アプローチ

専用の編集ルートを追加する案もあるが、今回の変更は詳細画面内の小さな操作追加であり、既存のプロジェクト作成ダイアログと同じ画面内ダイアログ方式が最も変更範囲と遷移を抑えられるため採用する。共有ナビゲーションバーには、現在のプロジェクトIDから `useProject` で取得した名前を渡し、詳細ルートだけを2階層のパンくずとして表示する。

## 実装上の判断

- 編集ボタンは `Edit project` とし、名前とワークスペースルートを編集対象にする。
- 削除ボタンは `Delete project` とし、プロジェクト名を含む確認ダイアログを表示してから削除する。
- 詳細画面の操作ラベルと見出しは英語UIの既存表記に合わせ、`New chat`、`Chats`、`No chats in this project yet.` を使用する。
