# 権限要求カードのデザイン

## 意図

会話中の権限許可要求を、参照されたCodex approval UIのように、要求内容と判断操作がすぐ把握できるカードに整える。既存テーマの色とコンポーネント表現を使う。

## 方針

- 要求の見出し、理由、アクセス範囲を視覚的に分け、パスなどの詳細を読み取りやすくする。
- 「今回のみ許可」「このチャットで許可」「拒否」を、内容の確認後に選ぶ操作としてカード下部に縦に並べる。
- 切断中や解決不可の状態は現行の無効化動作を維持する。
- App Serverの要求・応答形式と許可の意味は変更しない。他の承認、MCP要求、入力要求も変更しない。

## アプローチ

1. **既存カードを権限要求向けに整える（採用）** — 会話内の既存フローと操作場所を保ったまま、要求内容と操作の階層を明確にできる。
2. **別ダイアログに移す** — 詳細の表示領域は増えるが、他の保留リクエストと異なる導線になるため採用しない。
3. **すべての承認カードを一括で変更する** — 統一感は得られるが、今回の要望を超えて影響範囲が広いため採用しない。

## 制約と実装者への判断

- 色、角丸、余白、タイポグラフィは既存テーマとワークベンチのパターンに従う。
- 長いアクセスパスを省略して情報を隠さない。必要なら折返しや詳細表示を使う。
- アクセシブルな見出しと操作名を維持する。
- データとアクションの既存実装は再利用し、見た目の変更に必要な範囲だけを更新する。
