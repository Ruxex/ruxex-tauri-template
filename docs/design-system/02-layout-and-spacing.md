# レイアウトと余白

このガイドは、RuxexデスクトップUIのページ骨格、グルーピング、余白の使い分けを定めます。値はTailwind CSS 4の標準スペーシングスケールに合わせ、実装では既存のTailwindユーティリティを使います。独自CSS変数や新しいレイアウトコンポーネントを増やすことは、この段階の要件ではありません。

## 基準の単位

Tailwindの標準間隔は `0.25rem` 刻みです。現在のブラウザー基準では1刻みが4pxになります。全ての間隔を4px刻みに限定するのではなく、下の推奨値から役割に合うものを選び、隣り合う無関係な値を増やさないことを重視します。

| 用途 | 基準 | Tailwind例 | 使い方 |
| --- | ---: | --- | --- |
| 微調整 | 4px | `gap-1`, `p-1` | アイコンとラベルなど、同じ部品内の密接な要素。主要なグループ間隔には使わない。 |
| 密接な要素 | 8px | `gap-2`, `p-2` | 一覧の補助情報、ラベルと値、コンパクトな操作群。 |
| コンパクトな間隔 | 12px | `gap-3`, `px-3`, `py-3` | 関連する操作、一覧行、設定行など。隣接する枠付き操作にも使える。 |
| 標準の内側余白 | 16px | `gap-4`, `p-4` | 一般的なカード内部、フォーム内の関連項目、サイドバーの内側。 |
| ゆとりのある内側余白 | 20px | `p-5`, `gap-5` | 大きなカードや設定パネルなど、複数の要素を含む面。密度が必要な面では16pxに戻す。 |
| セクション間 | 24px | `space-y-6`, `gap-6` | 同じページ内の独立したセクション。ページコンテナの標準縦間隔。 |
| 大きな区切り | 32px | `gap-8`, `space-y-8` | 主題の異なる大きな領域の間。ページ内で繰り返し使いすぎない。 |

`gap-0.5`, `gap-1.5`, `p-3.5` のような中間値は、既存部品の密度や視覚調整に理由がある場合に限ります。新しい画面では、まず表の基準値を使い、細かな値を増やす必要が本当にあるか確認します。

## グルーピングのリズム

- 同じグループ内は近く、グループ間は明確に離します。目安として、グループ間は内部間隔の約2倍にします。
- 余白で区別できるなら線を足しません。背景面は、カードとして一体に見せる必要がある領域や選択状態に使います。
- 一覧、テーブル、履歴のように密度が高い領域では区切り線を使えます。その場合、同じ境界を大きな余白と線の両方で二重に表現しません。
- 同じ階層の要素は、共通の揃え位置と間隔を使います。入れ子になるごとに余白を一段進め、偶発的なずれを作りません。

## 余白の担当を分ける

- **`padding`** は面や操作要素の内側に空間を作ります。
- **`gap` / `space-y-*`** は兄弟要素や縦積みのまとまりの間隔を親側で管理します。
- **`margin`** は通常のグループ間隔の代わりに使わず、見出しとの視覚的な近接など、局所的な関係を調整するときに限ります。
- 同じ間隔を親の `gap` と子の `margin` の両方で作らないでください。コンテナに共通の縦リズムがある場合、子要素の上下余白を重ねず、そのコンテナを間隔の唯一の所有者にします。

## ページの骨格と幅

アプリシェルは通常のページに `p-4 sm:p-6` を与え、利用できる幅に応じて内容を配置します。会話やワークベンチのように広い作業面を必要とする画面は、ページ用の最大幅で無理に狭めません。フル幅が必要な領域では、アプリシェル側で余白を外す既存パターンもあります。

ページコンテンツは、内容に合った最大幅を選び、広ければ常に良いとは考えません。

| ページの性格 | 基準 | 用途 |
| --- | --- | --- |
| 広いページ | `max-w-5xl` | 一覧、複数カラム、表など横方向の情報が必要なページ。既存の `PageContainer` が基準。 |
| 集中して読む・設定するページ | `max-w-3xl` | 設定、詳細、単一カラムの編集フォーム。 |
| 作業面 | 最大幅なし、または作業領域に応じた幅 | 会話、ターミナル、差分など、作業領域が幅を使うページ。 |

幅の値はコンテンツの可読性と操作性から選びます。表や長い値がある場合は必要な幅を確保し、短い設定フォームは過度に広げません。共通の最大幅を変える場合は、個別ページだけで調整せず、同じ種類のページへの影響を確認します。

## ページとセクションの間隔

- ページコンテナの標準は、共通の横幅・中央寄せと `space-y-6` によるセクション間隔です。既存の `PageContainer` がこの実装例です。
- ページヘッダーは、タイトル側と操作側を一まとまりとして配置します。横幅が足りないときは折り返し、操作がタイトルや本文に重ならないようにします。項目間は通常 `gap-4` を基準にします。
- ページコンテナが兄弟セクションの間隔を持つ場合、ヘッダーの `padding-bottom` と次のセクションの `padding-top` を慣例で重ねません。レイアウトの親か局所要素のどちらが間隔を持つか明確にします。
- 設定画面では、カード単位の余白とページ全体の余白を分けます。カードの内部は通常16〜20px、カード間はページのセクション間隔に従います。

## 部品別の基準

### フォーム

- ラベルと入力欄、入力欄と短い状態表示は近づけ、同じ項目として読めるようにします。
- 同じ項目内の小さな間隔は4〜8px、関連する操作や補助情報は8〜12px、項目群の間は16pxを基準にします。
- 別の設定グループは24px以上離すか、明確な見出し・面で区別します。
- 入力や説明が長くなることを前提に、固定高ではなく内容に応じて伸びるレイアウトを使います。

### 一覧とナビゲーション

- 一覧では主要名、状態、補助情報の順に視線を導き、同じ役割の情報を同じ端に揃えます。
- 行内のアイコンとラベルは通常8px前後、行の内側余白は密度に応じて8〜12pxを起点にします。
- 頻繁に走査する一覧は、カード間の大きな空白を避けます。まとまりが必要な場合は、セクション間に24px程度の差をつけます。
- クリックできる行や操作群は、周囲の静的な説明と見分けられる配置、背景、境界、または一貫した操作領域を持たせます。

### 操作群

- 枠や塗りのある隣接操作は、通常12px程度離します。
- 枠のないアイコン操作は境界が分かりにくいため、操作対象同士をより離すか、明確なツールバー領域にまとめます。
- 主操作はその画面の主目的に合わせ、関連する内容の近くに置きます。操作が増えた場合は、優先度を整理して表示領域を圧迫しないようにします。
- 全幅の操作ボタンもページの本文幅に揃え、通常の内容領域では画面端に貼り付けません。

### ダイアログとポップオーバー

- ダイアログは内容に合った最大幅を使い、ビューポート内に収めます。内容が長い場合は本文をスクロール可能にし、操作が見つけられなくならない構成にします。
- 内側の標準余白は16〜24pxを起点にします。フォームや確認などの目的で必要な場合のみ、局所的に増減します。
- ポップオーバーは起点の操作に近づけ、画面端や他の重要操作と重ならない配置にします。

## 狭い領域と可変コンテンツ

Ruxexのメインウィンドウは初期幅1280px、最小幅960pxです。ただし、サイドバー、分割ペイン、ダイアログなどはメインウィンドウより狭くなるため、ウィンドウ幅だけでなく各ペインの実際の幅で成立するか確認します。

- レイアウトは内容が収まらなくなる位置で切り替えます。再利用コンポーネントは可能なら親コンテナの幅に応じて対応させます。
- 長い文字列や表のあるフレックス／グリッド項目には、必要に応じて `min-w-0` や `minmax(0, 1fr)` を使い、隣の領域やウィンドウを押し広げないようにします。
- 固定幅はアイコン列など内容が一定の部品に限定します。ラベル、ボタン、説明文は内容に応じて伸びるか折り返すようにします。
- コンテンツを省略する場合、重要な値は詳細表示、展開、キーボードでも使えるツールチップなどから完全な値へ到達できるようにします。
- ビューポート幅を使った `100vw` は、スクロールバー分のはみ出しを避ける必要がある通常の内容幅には使いません。
- 固定高で文章やフォームを切らず、必要なら `min-height` と内部スクロールを使います。
- 左右方向に依存する余白は、可能な範囲で論理プロパティに対応するTailwindユーティリティ（`ms-*`, `me-*`, `ps-*`, `pe-*`, `text-start` など）を使います。

## Tailwindでの基本形

```tsx
<PageContainer>
  <header className="flex flex-wrap items-end justify-between gap-4">
    <h1 className="text-3xl font-semibold">Projects</h1>
    <div className="flex flex-wrap items-center gap-3">
      {/* 関連する操作 */}
    </div>
  </header>

  <section className="space-y-4">
    {/* 見出しと内容を同じグループに置く */}
  </section>
</PageContainer>
```

この例はレイアウトの関係だけを示します。`PageContainer` がすでに最大幅とセクション間隔を管理するため、ページ要素に同じ間隔を追加しません。状態、操作、意味のある見出しは各機能に合わせて実装します。

## 例外を選ぶとき

次のような場合は基準を変えて構いません。例外は「見た目を変えたい」だけでなく、利用状況または内容に結びつけて判断します。

- 会話履歴、ターミナル、差分、テーブルなど、連続して読んだり比較したりする密度の高い作業面。
- 分割ペインや狭いサイドバーのため、標準の内側余白では有効幅が不足する領域。
- ダイアログ内で、長いフォームや長文の確認を扱う領域。
- 選択・ドラッグ・状態表示など、操作の境界や意味を背景・境界で伝える必要がある領域。

## レビュー時の確認

- 同じ役割のページと部品で、同じ余白・幅・揃え位置を使っているか。
- グループ内よりグループ間の間隔が広く、余白、背景、線を重ねすぎていないか。
- 親の `gap` と子の `margin` / `padding` が同じ間隔を二重に作っていないか。
- ウィンドウを最小幅にし、サイドバーや右ペインも開閉・リサイズして、内容と操作を失わないか。
- 長いProject名、Thread名、ファイルパス、エラー文がある状態で、レイアウトが横にはみ出したり操作を押し出したりしないか。
- キーボード操作、フォーカス表示、拡大表示でも、配置が意味や操作可能性を損なわないか。

## 現行コードとの対応

この初版の基準は、現在のコードで使われている共通パターンを整理したものです。たとえば、[`PageContainer`](../../src/components/layout/PageContainer.tsx) は `max-w-5xl` と `space-y-6` を使い、[`AppLayout`](../../src/components/layout/AppLayout.tsx) は通常ページに `p-4 sm:p-6` を与えています。設定・詳細ページには `max-w-3xl` の例があります。

これらはガイドの根拠となる既存例であり、現状の全ページを監査した結果ではありません。適用フェーズでは、各画面を確認したうえで、同じ役割の差異をガイドに合わせて段階的に整理します。
