# UI fixture操作ルール

UI fixtureは、ユーザーがデスクトップアプリを使うときと同じ経路で操作します。

## 操作方法

- アプリ内の状態を変える操作は、画面上のクリック・キー入力・フォーム入力で行います。WDIOの通常の要素操作を使ってください。
- ネイティブダイアログなど、WDIOから直接操作できない画面では、AT-SPIなどのアクセシビリティ操作を使えます。
- AppServerプロトコルをfixtureから直接送ること、Tauriの内部コマンドや`invoke`をfixtureから呼ぶことは禁止です。DOMイベントを直接発火して画面操作を迂回する方法も使いません。
- テスト用ファイルやGitリポジトリなど、アプリ起動前の環境準備はスクリプトで行えます。アプリ内データの作成や変更はGUIまたはアクセシビリティ経由で行ってください。

## 問題が起きたとき

失敗した場合は、操作をまとめて再試行したり、待ち時間を闇雲に増やしたりせず、インタラクティブ実行で落ち着いて切り分けます。

1. アプリを起動し、その実行中のセッションにWDIOを接続します。
2. GUIまたはアクセシビリティ経由で、一度にひとつの操作を実行します。
3. 操作後の画面、アクセシビリティ状態、WDIOログを確認して、どの段階で期待と違ったか記録します。
4. アプリの挙動、fixtureの入力方法、待機条件、要素の特定方法を分けて原因を絞ります。
5. 再現できる最小のケースで修正し、同じ操作をインタラクティブに再確認してからfixture全体を実行します。

確認には画面とアクセシビリティツリー、WDIOログ、fixtureのスクリーンショットを使います。fixtureがアプリ内部の通信や状態を直接操作して、失敗を回避してはいけません。
