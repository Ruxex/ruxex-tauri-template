# 部品の内側余白と操作サイズ

このガイドは、ページやグループ間の余白ではなく、ボタン、入力欄、アイコン操作など**部品そのものの寸法**を揃えます。外側の配置と間隔は[レイアウトと余白](./02-layout-and-spacing.md)、部品の意味や状態の見た目は各コンポーネントガイドで定義します。

## 基本ルール

1. **部品の寸法は部品のクラスで選ぶ。** DaisyUIの `btn`、`btn-sm`、`btn-xs`、`input`、`input-sm` などを使い、同じサイズを `h-*`、`py-*`、`p-*` の組み合わせで作り直しません。
2. **内側の余白と隣の要素との間隔を分ける。** ボタン内のアイコンとラベルの間はボタンの `gap`、ボタン同士の間は親コンテナの `gap` が担当します。
3. **`padding` はタップ／クリック領域の一部として扱う。** 見た目のアイコンだけを小さくしても、操作できる箱まで小さくしません。
4. **一つのコントロールにサイズ指定を重ねない。** DaisyUIのサイズと任意の高さ・paddingを同時に指定するのは、コンポーネント仕様として理由がある場合に限ります。

## Ruxexの操作サイズ

標準ボタンと入力欄は、現在のDaisyUI設定で高さ40pxです。コンパクトサイズは `sm` が32px、`xs` が24pxです。ボタンはサイズに合わせて横方向の内側余白も変わります。

| 役割 | 推奨クラス | 現在の高さ | ボタンの横padding | 使いどころ |
| --- | --- | ---: | ---: | --- |
| 標準操作 | `btn` / `input` / `select` | 40px | ボタン16px、入力・選択欄12px | ページの主要操作、通常のフォーム項目、日常的に使う操作 |
| コンパクト操作 | `btn-sm` / `input-sm` / `select-sm` | 32px | ボタン12px、入力・選択欄12px | カード内の副次操作、密度の高いツールバー、補助的なフォーム |
| 高密度の補助操作 | `btn-xs` / `input-xs` / `select-xs` | 24px | ボタン8px、入力・選択欄12px | 操作頻度と重要度が低い補助領域。周囲との間隔を十分に取れる場合 |
| ゆとりのある主要操作 | 標準クラス + `min-h-11` | 最低44px | 標準の横paddingを維持 | 新規作成、フォーム送信など、目立たせたい主要操作 |

ボタンのアイコンとラベルの間隔は、標準操作では `gap-2`（8px）を使います。コンパクトな副次操作では `gap-1`（4px）まで詰められます。アイコンのないボタンに空のgapやpaddingを追加しません。

この表のDaisyUI寸法は、現在プロジェクトで使っているコンポーネント既定値を記録したものです。DaisyUIを更新したときは、既定値を確認してこの表も更新します。ライブラリの値を別のCSS変数へ複製するのは、Ruxex固有の意味を持つ値として複数箇所で再利用する必要が明確になってからにします。

## ボタン

### テキストボタン

- 標準の主操作は `btn`、面積を少し強めたい主要操作は必要に応じて `min-h-11` を加えます。
- カードや一覧内の副次操作は `btn-sm` を使います。`btn-xs` は常時操作するアクションの標準にはしません。
- サイズクラスが高さと横paddingを決めるため、ボタン自身に `p-*`、`px-*`、`py-*` を追加しません。ラベルが長い場合はボタンの幅や親レイアウトを調整し、ラベルを切り詰めて収めません。
- アイコンと文字の両方がある場合は `gap-2` を付けます。詰まったツールバーに限り `gap-1` を選べます。

```tsx
<button className="btn btn-primary min-h-11 gap-2" type="button">
  <PlusIcon aria-hidden="true" className="size-4" />
  New project
</button>
```

### アイコンだけのボタン

- DaisyUIの `btn-square` または `btn-circle` を使い、幅と高さを同じサイズにします。
- 画面上のアイコンが16pxでも、標準の操作領域は40×40pxを起点にします。密度が必要なデスクトップ領域でも32×32pxを優先し、24×24px未満には縮めません。
- `size-4 min-h-4 p-0` のように、操作箱そのものをアイコンサイズへ縮める指定は避けます。装飾的に見えないアイコン操作には、常に明確なフォーカス表示とアクセシブルな名前を付けます。
- **バッジ内の解除ボタンと選択済みスキルの解除ボタンは例外**とし、周囲の部品に収めるためのコンパクトな寸法・padding・配置を許容します。この例外でも、解除ボタンを独立した操作として実装し、アクセシブルな名前とフォーカス表示を保ちます。
- **チャットComposerは高頻度作業面として密度を優先する例外**です。常時表示する送信操作は32pxのアイコンボタン、プロジェクト選択は24pxのコンパクトな選択操作を使えます。送信ボタンの可視ラベルは省き、`aria-label` と `title` で操作名を保ちます。高さを周囲の標準操作へ揃えることより、入力欄を広く保ち、反復操作で視線とポインターの移動を抑えることを優先します。
- 操作同士は[レイアウトガイド](./02-layout-and-spacing.md)の間隔を保ち、ヒット領域を重ねません。

## 入力欄と選択欄

- DaisyUIの `input`、`select`、`textarea` の既定paddingを使います。特別な密度が必要な場合は、個別paddingではなく対応するサイズバリアントを選びます。
- `input` と `select` は標準40px、コンパクト32pxを基本とします。フォームの主要項目で `xs` を使わないでください。
- `select` の末尾側の余白は矢印表示のために広く取ります。左右対称に上書きせず、DaisyUIの既定値を保ちます。
- `textarea` は横方向に `p-3` を起点とし、文章量に合わせて高さを伸ばすか、必要な場合だけ最小高さを指定します。本文が増えた状態で上下が窮屈にならないようにします。
- 入力欄のアイコン、クリア操作、単位表示は、入力文字との間隔を8px前後に保ちます。アイコンを入力欄のpadding代わりに置かず、コントロールの内側レイアウトに含めます。

## バッジ、チップ、状態ラベル

- `badge` や `badge-sm` など、意味に合ったDaisyUI部品の既定寸法を使います。バッジのpaddingをボタンと同じにしません。
- バッジは情報表示です。操作可能なチップとして振る舞う場合は、操作部分を実際の `<button>` またはリンクにし、バッジの外観と操作のヒット領域を混同させません。
- バッジ内の解除ボタンは上記の寸法例外を適用できます。独立したボタンの名前とフォーカス表示を保ち、隣接する文字や操作と重ねません。

## 例外の扱い

小さな `btn-xs` や任意のpaddingが必要な場合は、次のすべてを満たすときに限ります。

- 画面が高密度で、標準サイズでは作業領域を不必要に圧迫する。
- 重要度と操作頻度が低く、主要操作と混同されない。
- 操作可能なターゲットが24×24px以上で、隣接ターゲットと重ならない。
- キーボードのフォーカス表示とアクセシブルな名前が残る。
- そのサイズを選ぶ理由が同種の部品にも再利用できる。

例外が複数画面に広がった場合は、個別のpadding指定を増やさず、サイズバリアントや共通部品の不足として見直します。

## 現行コードとの対応

標準 `btn` は [`ProjectsPage`](../../src/pages/ProjectsPage.tsx) や [`SchedulesPage`](../../src/pages/SchedulesPage.tsx) の主要操作で使われ、`min-h-11` を加えた44px以上の例もあります。標準 `input` と `select` は [`ChatsPage`](../../src/pages/ChatsPage.tsx)、コンパクトな入力欄は [`ProjectSelector`](../../src/components/composite/chats/ProjectSelector.tsx) に例があります。

これらはガイドの寸法を説明する参照例です。全ての既存ボタン・入力欄を監査した結果ではなく、既存画面への適用は別の工程です。
