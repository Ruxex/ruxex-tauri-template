# コンポーネントと状態のパターン

このガイドは、部品の外観を一覧化するカタログではなく、同じ役割の操作・情報に共通する構造と状態を定めます。色と文字の意味は各基礎ガイド、内側寸法は[部品の内側余白と操作サイズ](./03-component-spacing.md)に従います。

## アクション

- 主要操作はビューまたは操作群ごとに一つを明確にします。主要操作は内容の近くに置き、二次操作はアウトラインまたはゴーストなど既存の軽い表現で並べます。
- 破壊的操作は通常の主要操作と同じ強さで並べません。実行前に対象と結果が分かる名前を使い、取り消せない操作は確認ダイアログで影響を示します。
- 頻繁に使う操作を隠れたホバーだけで提供しません。ホバーで補助操作を出す場合も、キーボードフォーカス時には表示します。
- 同じ目的の操作にテキスト、アイコン、塗り、サイズの異なる慣例を増やしません。視認性や密度に根拠がある場合は例外として記録します。

## フォーム

- 入力には常時見えるラベルを付け、placeholderだけをラベルにしません。関連する補助説明とエラーは入力に近づけます。
- 必須、無効、選択中、読み込み中の状態は、利用者が視覚と支援技術の両方で理解できるようにします。
- エラーは該当項目に結びつけ、何が問題かと次にできることを簡潔に伝えます。送信時の検証を基本とし、エラーを色だけで示しません。
- 同じフォーム内では、ラベル、入力欄、エラー、次の項目の間隔を[レイアウトガイド](./02-layout-and-spacing.md)のフォーム規則で揃えます。
- 送信中は進行中であることを示し、操作が多重実行されないようにします。表示文言の置き換えでボタン幅が大きく変わる場合は、レイアウトの安定を保ちます。

## 選択とナビゲーション

- ナビゲーションは現在位置、選択状態、開閉状態を色だけでなく形や属性でも示します。
- タブ、選択リスト、トグルは一つの選択状態の意味を共有し、同じ画面で複数の別表現を使いません。
- タブが同じ領域内の内容を切り替える場合、タブ列とペインを連続した一つの面として扱います。選択中のタブは前面にあるように上辺と左右の境界を見せ、ペイン上端の境界をその幅だけ隠します。非選択タブはペインから独立したカードに見せません。
- タブは `tablist`、`tab`、`tabpanel` の意味関係を持たせ、選択状態を `aria-selected` で示します。矢印キーでタブ間を移動でき、Tabキーでは選択中タブからペインへ進めるようにします。フォーカスリングを境界や隣接面で見失わせません。
- 実際に画面遷移する項目はリンク、状態を変更する項目はボタンを使います。クリック可能な`div`や`span`を操作要素として再現しません。
- 行全体を操作可能にする場合、行内にある別操作とクリック領域を衝突させず、キーボードでも同じ結果に到達できるようにします。

曜日など固定数の選択肢を枠内に並べる場合、選択肢のグループを枠の中央に置き、各項目の間隔を均等にします。幅が狭い画面でも項目が枠からはみ出さないようにします。

## ダイアログ、メニュー、ポップオーバー

- ダイアログは一つのタスクに集中させ、タイトル、本文、操作領域を視覚的に区別します。幅は内容に合わせ、長い本文が操作を押し流さないようにします。
- ダイアログを開いたときはフォーカスを内部へ移し、閉じたときは起動元へ戻します。Escape、キーボード移動、背面操作の抑止はネイティブ機能を優先します。
- メニューとポップオーバーは起動した操作との関係が分かる位置に置き、ビューポート端で内容が欠けないようにします。
- オーバーレイ内のスクロールは背面ページへ連鎖させません。スクロール内容が長い場合もタイトルまたは閉じる操作への経路を保ちます。

## 非同期・状態表示

| 状態 | 表示の原則 |
| --- | --- |
| Loading | 実際の待ち時間がある領域に表示し、可能なら対象のレイアウトを保つ。スピナーだけに意味を任せない |
| Empty | 「データがない」と「読み込みに失敗した」を区別し、次に必要な操作だけを示す |
| Error | 失敗した対象、問題、再試行や復帰方法を伝える。エラー色に加えてテキストを表示する |
| Success | 完了した状態を明示し、繰り返し通知で作業を遮らない |
| Disabled | 操作不能の理由が必要なときに利用者が理解できる手掛かりを置く。単に薄くして終わらせない |
| Selected / Active | 選択された項目と現在の作業状態を別の意味として扱い、混同させない |

自動的に消える通知へ、エラーの解決に必要な情報や取り消し操作を唯一の形で置きません。動的な更新は適切なライブリージョンで通知し、頻繁な状態変化を読み上げ続けないようにします。

## 面、境界、アイコン、動き

- 面はコンテンツのまとまり、境界は分離・入力・選択などの役割がある場合に使います。影と線で同じ階層を二重に表しません。
- DaisyUIの `rounded-box`、`rounded-btn`、`shadow-sm` など既存の語彙を優先し、新しい半径・影を増やす場合は複数の部品で再利用する理由を示します。
- アイコンは一つのUI面の中で既存ライブラリとアウトライン／塗りの慣例を保ちます。アイコン単独操作にはアクセシブルな名前と見えるフォーカス表示を付けます。
- 高頻度のホバー、選択、タブ切替は即時または短い遷移に留めます。アニメーションは状態の唯一の手掛かりにせず、`prefers-reduced-motion` を尊重します。
- モーダルやメニューの背面がスクロールしたり、ポインター向けホバーがタッチで固定表示になったりしないようにします。

## 実装参照例

現在の共通部品を新しい画面へ流用する前に、その部品が状態・キーボード操作・可変内容まで同じ役割を持つか確認します。例として、ダイアログの骨格は [`DialogShell`](../../src/components/base/common/DialogShell.tsx)、非同期状態の簡潔な表示は [`AsyncState`](../../src/components/base/common/AsyncState.tsx)、バッジ状態の意味表現は [`StateBadge`](../../src/components/base/common/StateBadge.tsx) を参照できます。

既存部品がない場合は、次の[参照パターン](./07-reference-patterns.md)を基に、機能に必要な意味・振る舞いを追加します。見た目だけ似せた独自部品は作りません。
