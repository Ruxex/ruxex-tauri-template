# Ruxex 0.3.2 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Update the Tauri backend to Ruxex `v0.3.2` and prefer the public `ruxex` facade wherever the required API is exposed.

**Architecture:** Pin all Ruxex Git dependencies to the `v0.3.2` tag. Add the `ruxex` facade with only its `app-server` feature, replace direct imports for facade-exposed APIs, and retain only the internal client/protocol/daemon/path crates whose APIs are not re-exported by the facade.

**Tech Stack:** Rust 2024, Cargo, Tauri 2, Ruxex Git workspace.

**Spec:** User request: migrate Ruxex to version 0.3.2 and use the public facade instead of internal crates where possible.

## Global Constraints

- Ruxex dependencies must resolve from `https://github.com/Ruxex/ruxex.git` at tag `v0.3.2`.
- Preserve the existing uncommitted frontend changes in the main worktree.
- Use `ruxex` facade APIs where `v0.3.2` exposes the required functionality.
- Do not introduce a registry-only `ruxex = "0.3.2"` dependency; Ruxex is Git-distributed.

## Review Focus

- Manifest and lockfile must resolve one consistent Ruxex `0.3.2` Git revision.
- Existing app-server client, protocol, daemon bootstrap, and absolute-path behavior must continue compiling and testing.
- The facade must not enable unnecessary CLI/TUI features for the desktop host.
- Existing unrelated working-tree changes must remain untouched.

### Task 1: Update Ruxex dependencies and facade imports

**Files:**
- Modify: `src-tauri/Cargo.toml`
- Modify: `src-tauri/src/lib.rs`
- Update: `src-tauri/Cargo.lock` via Cargo

**Interfaces:**
- Consumes: Ruxex `v0.3.2` facade exports `ruxex::ProductIdentity` and `ruxex::app_server::app_server_control_socket_path`.
- Produces: A backend that resolves Ruxex dependencies at `0.3.2` and uses the facade for exposed APIs.

- [x] **Step 1: Change the manifest**

Add `ruxex` from the Ruxex Git repository at tag `v0.3.2` with `default-features = false` and `features = ["app-server"]`; update retained direct Ruxex dependencies to version `0.3.2`, tag `v0.3.2`; remove the direct home-directory dependency when its API is replaced by the facade.

- [x] **Step 2: Update imports and facade calls**

Use `ruxex::ProductIdentity` and `ruxex::app_server::app_server_control_socket_path`; keep direct client/protocol/daemon/absolute-path imports only where the facade does not expose equivalent APIs.

- [x] **Step 3: Resolve the lockfile**

Run `cargo check --manifest-path src-tauri/Cargo.toml` so Cargo updates `src-tauri/Cargo.lock` to the `v0.3.2` revision.

- [x] **Step 4: Run verification**

Run `cargo test --manifest-path src-tauri/Cargo.toml` and the repository frontend test command. Confirm no Ruxex dependency remains at the old Git revision and no unrelated files changed.

- [x] **Step 5: Review the diff**

Run `git diff -- src-tauri/Cargo.toml src-tauri/Cargo.lock src-tauri/src/lib.rs` and `git status --short`; report any pre-existing changes separately.
