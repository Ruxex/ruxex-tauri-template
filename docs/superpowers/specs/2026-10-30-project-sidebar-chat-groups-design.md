# Project Sidebar Chat Groups Design

## Intent

サイドバーの Projects セクションで、各プロジェクトを個別に展開し、そのプロジェクトに属するスレッドをサーバーの recency 順で表示する。プロジェクトページへの遷移は既存どおり維持し、開閉操作とは分離する。

チャット名はサイドバーの利用可能幅を超えた場合に省略記号で切り詰め、ステータスアイコンや他の行要素の位置を動かさない。

## Goals

- Projects セクション内の各プロジェクトを個別に開閉できる。
- 展開時に、対象プロジェクトのスレッドだけを表示する。
- プロジェクト内のスレッドは `recency_at` 降順で表示する。
- プロジェクト名をクリックすると、従来どおりプロジェクトページへ遷移する。
- チャット名が長い場合はサイドバー内で `…` 表示にする。
- ステータスアイコン、選択状態、既存のサイドバー開閉挙動を維持する。

## Non-goals

- スレッド一覧をクライアント側で全件取得して再グループ化すること。
- プロジェクトやスレッドの並び順を変更すること。
- プロジェクトページやチャット画面のレイアウトを変更すること。
- プロジェクト名やチャット名を編集する機能を追加すること。

## Constraints

- App Server のスレッド・プロジェクト情報を唯一のデータソースとする。
- 既存の `ThreadList` と `projectThreadListParams` を再利用する。
- プロジェクトページへのリンクと開閉操作は別の操作として実装する。
- プロジェクトの開閉は画面表示中のローカルな UI 状態に限定し、永続化しない。
- チャット名の省略は CSS のレイアウトで行い、DOM 上の完全な名称とアクセシブルなリンク名は維持する。

## Approaches

### 1. Project row with separate disclosure control — chosen

各プロジェクトを、開閉ボタン・プロジェクトページリンク・展開された `ThreadList` からなる行として表示する。開閉ボタンはプロジェクト単位の状態を切り替え、プロジェクト名リンクは `/projects/:projectId` へ遷移する。既存の `ThreadList projectId={...}` がプロジェクト単位の API クエリと `recency_at desc` を担当する。

開閉操作とページ遷移が明確に分離され、既存のナビゲーションを壊さないため採用する。初期状態は閉じた状態とし、サイドバーの高さを不必要に増やさない。

### 2. Native details around the whole project row

`<details>/<summary>` を使い、プロジェクト行全体を開閉領域にする。実装は簡潔だが、プロジェクトページへのリンクと開閉操作が同じ領域になるため、操作の意図が曖昧になる。

### 3. Client-side grouping of one global thread list

全スレッドを一括取得してプロジェクトごとにグループ化する。リクエスト数は抑えられる可能性があるが、取得件数、ページング、更新、プロジェクト別の並び順をクライアント側で管理する必要があり、既存の App Server クエリ境界に反する。

## Implementation shape

- `ChatSidebarSections` にプロジェクトごとの開閉状態を追加する。
- Projects の各行に固定幅の開閉アイコンボタンを配置する。
- 展開時のみ `ThreadList` に `projectId` と現在の選択スレッド ID、既存の `onClose` を渡す。
- `ChatListItem` のタイトル領域を可縮小な flex item にし、`truncate` を確実に適用する。
- コンポーネントテストで、複数プロジェクトの独立した開閉、プロジェクト内スレッドの順序パラメータ、長いチャット名の省略用クラスを固定する。
