# Ruxex Design System

Ruxex のデスクトップUIで、画面をまたいだ判断と実装を揃えるための指針です。哲学、レイアウト、部品寸法、色、文字、操作パターンを定め、参照例と運用ルールまで一か所にまとめます。

## このディレクトリの読み方

1. [デザイン哲学](./01-philosophy.md) — 何を大切にし、判断が衝突したとき何を優先するか。
2. [レイアウトと余白](./02-layout-and-spacing.md) — 画面の骨格、間隔、幅、グルーピングをどう決めるか。
3. [部品の内側余白と操作サイズ](./03-component-spacing.md) — ボタン、入力欄、アイコン操作の内側寸法をどう揃えるか。
4. [色とテーマ](./04-color-and-theme.md) — テーマ色を役割に結び付け、状態やコントラストをどう扱うか。
5. [文字とコンテンツ](./05-typography.md) — 文字階層、読み幅、可変文字、ユーザー設定への対応。
6. [コンポーネントと状態のパターン](./06-component-patterns.md) — 操作、フォーム、選択、ダイアログ、非同期状態をどう揃えるか。
7. [画面・部品の参照パターン](./07-reference-patterns.md) — ガイドに沿ったコード断片とその利用条件。
8. [適用・レビュー・ガイドの運用](./08-adoption-and-governance.md) — 実装レビュー、例外、段階導入、文書改訂の手順。

## 状態と適用範囲

- **段階:** 哲学とガイドの初版。ここで定める段階5までの作業は、指針・参照例・運用手順の文書化です。プロダクトコードへのトークン導入や既存画面への適用はまだ行っていません。
- **対象:** `ruxex-tauri-template` のRuxexデスクトップUI。ワークベンチ、ページ、設定、サイドバー、ダイアログのレイアウトと、ボタン・フォームコントロールなど部品内部の寸法。
- **対象外:** プロダクトUIへの実装・反映、共通トークンの導入、共通コンポーネントの追加・改修、既存画面の一括移行。
- **実装の前提:** Tailwind CSS 4 と DaisyUI を継続して使います。ガイドの例は現在の実装方式に合わせています。

このガイドは今後の新規・変更UIで使う判断基準です。既存画面すべてがすでにこの規約に沿っている、という意味ではありません。適用はガイドのレビュー後に別の作業として進めます。

## 成熟させる5段階

1. **哲学:** 製品として守る原則と判断の優先順位を共有する。
2. **視覚基盤:** レイアウト、余白、部品寸法、色、文字の役割と基準を定める。
3. **コンポーネントと状態:** 操作、フォーム、選択、オーバーレイ、非同期状態の共通パターンを定める。
4. **参照例:** 代表的なページ・フォーム・状態遷移のコード例を、ドキュメント内の参照用サンプルとして整える。
5. **運用と適用準備:** レビュー、例外、改訂と、将来の段階的な実装を始める条件を定める。ここまでが今回のゴールで、プロダクトへの実装・反映は別工程とする。

このディレクトリは段階1〜5の文書成果物を提供します。将来コードに適用するときは全画面を一度に置き換えず、代表ページや部品で検証してから適用範囲を広げます。同じ判断が複数の異なる画面で繰り返されると確認できた場合に限り、意味のあるトークンや共通部品として抽出します。

## 変更の考え方

- 既存の共通パターンを先に確認し、同じ役割には同じルールを使います。
- 新しい値や部品は、繰り返し現れる判断を減らせるときに追加します。
- 例外は目的が説明できる場合に限ります。密度、狭いペイン、長いコンテンツなど、画面固有の条件を理由にできます。
- 迷ったら、製品のデータ境界とアクセシビリティを守り、構造を余白で伝え、装飾を後から足します。
- 「標準」「〜します」は既定の選択を表します。「目安」「基準」は出発点で、密度やペイン幅などの根拠があれば調整できます。
