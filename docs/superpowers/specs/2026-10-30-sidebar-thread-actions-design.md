# Sidebar Thread Actions Design

## Intent

サイドバーの最近のチャットと展開されたプロジェクト内スレッドに、各スレッドをすぐアーカイブできるアイコン操作を追加する。長いスレッドタイトルは通常の省略表示を保ち、ホバー時だけ文末までゆっくりスライドして確認できるようにする。

## Goals

- 各サイドバースレッド行の右端にアーカイブ用のアイコンボタンを置く。
- ボタンは通常は控えめにし、行のホバーまたはキーボードフォーカスで表示する。
- アーカイブ操作はチャットリンクの遷移を発生させず、App Server の `thread/archive` を呼ぶ。
- 最近のチャットとプロジェクト別スレッドの両方で同じ操作を使う。
- タイトルが表示領域を超える場合だけ、ホバー時に末尾までゆっくりスライドする。
- アニメーション中もステータスアイコンとアーカイブボタンの位置を固定する。

## Non-goals

- アーカイブ済みページのレイアウトや復元操作を変更すること。
- チャットリンク内にボタンを入れること。
- タイトルを自動的に変更したり、タイトル全文を常時表示すること。
- 新しい永続化状態や独自のアーカイブキャッシュを追加すること。

## Constraints

- アーカイブは既存の `useArchiveThread` と App Server の `thread/archive` を使う。
- `ThreadList` がアーカイブミューテーションを所有し、行へコールバックと pending 状態を渡す。
- アーカイブボタンはリンクの外側に置き、クリック時にリンク遷移を発生させない。
- タイトルの完全な文字列はDOMとアクセシブルな名前に残す。
- タイトルの溢れ量はレイアウト計測で判定し、溢れていない短いタイトルにはスライドを適用しない。
- アニメーションはCSS transitionを使い、タイトルの溢れ量だけ負方向へ移動する。

## Approaches

### 1. Separate row controls with shared ThreadList mutation — chosen

`ChatListItem` をリンクとアーカイブボタンの兄弟要素に分け、`ThreadList` が `useArchiveThread` を一度だけ呼び出して各行へ `onArchive` と pending 状態を渡す。タイトルは測定用のラッパーと通常表示・スライド表示を重ね、ホバー時に溢れ量だけ変形する。

リンク遷移とアーカイブ操作が明確に分離され、最近のチャットとプロジェクト別一覧で同じ実装を再利用できるため採用する。

### 2. Button inside the chat link

見た目はまとめやすいが、`button` を `a` の中に置くことになり、クリック・キーボード操作・アクセシビリティが不安定になる。

### 3. Context menu for archive

行の見た目を保ちやすいが、右端の直接操作という要件を満たさず、目的の操作までの手数も増える。

## Implementation shape

- `ThreadList` に `useArchiveThread`、アーカイブボタンのコールバック、pending 状態を追加する。
- `ChatListItem` に任意の `onArchive` と `isArchiving` を追加し、`ArchiveBoxIcon` のアイコンボタンを行右端にレンダリングする。
- アーカイブ操作は `preventDefault` と `stopPropagation` でリンク遷移を防ぐ。
- `ChatListItem` 内に、タイトル幅と内容幅を測る小さな表示コンポーネントを追加する。
- 長いタイトルには `title` 属性とキーボードでも到達可能なホバー領域を維持する。

## Verification

- アーカイブボタンの表示、アクセシブルな名前、クリック時のコールバック、リンク遷移抑止をテストする。
- 最近のチャットとプロジェクトスレッドが `useArchiveThread` を共有することをテストする。
- タイトルの短い状態ではスライドを無効にし、長い状態ではホバー用の transition と計測結果を使うことをテストする。
- フロントエンド全体の型チェック、Lint、テスト、ビルドを実行する。
- `git diff --check` を実行する。
